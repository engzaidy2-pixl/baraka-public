---

## 📖 نظرة عامة

**نظام شؤون العضوية** هو قلب منصة **بركة** لإدارة الجمعيات الأهلية: يتتبّع العضو من لحظة الانتساب حتى سداد اشتراكاته، سواء نقدًا أو عبر خصم الرواتب.

النظام مصمم لواقع الجمعيات العربية: عضو أساسي (عامل/متقاعد) يرتبط به منتسبون (زوجة، أبناء، والدين)، وكل عضو تابع لجهة عمل وجهة خصم (إدارة استحقاقات)، والأسعار قد تُرفع سنويًا فيُخصم الفارق عن الأعضاء تلقائيًا عبر **تسويات** موثقة.

### 🎯 المشكلة التي يحلها

| قبل بركة | بعد بركة |
|---|---|
| كشوش Excel متفرقة وغير محمية | قاعدة بيانات مركزية بصلاحيات RLS لكل دور |
| حساب الاشتراكات والتأخر يدويًا | اشتراكات شهرية/سنوية بحالة فورية لكل عضو |
| رفع الأسعار يعني مراجعة كل عضو | تسوية سعرية واحدة تُطبَّق على الأشهر المتأثرة تلقائيًا |
| خطابات خصم الرواتب تُكتب يدويًا | دفعة خصم مجمعة لكل جهة شهريًا + خطاب جاهز للطباعة |
| لا سجل تاريخي للأسعار | سجل أسعار تاريخي كامل بتاريخ سريان |

## ✨ المزايا الرئيسية

- 👥 **إدارة الأعضاء** — يدعم 2000+ عضو: بيانات أساسية، تواصل (هاتف/واتساب/بريد)، وظيفة ورقم موظف وراتب، مع بحث سريع بالاسم والرقم الوطني ورقم العضوية.
- 🌳 **بنية هرمية** — منتسبون مرتبطون بعضو أساسي (`parent_member_id` + صلة القرابة)، مع حد أقصى للتابعين لكل فئة وإمكانية تجاوزه (`max_dependents_override`).
- 🏢 **جهات عمل ← جهات خصم (1:N مباشرة)** — كل جهة خصم تتبع جهة عمل واحدة (`deduction_entities.employer_id`)، ولكل جهة عمل **صف ذاتي** (`is_self`) يمثلها كجهة خصم حين لا فروع لها، مع مفتاح «لها جهات استحقاق فرعية» (`employers.has_deduction_entities`) يفتح إدارة الفروع. الجهات المستقلة تُضمّ للحاوية «جهات حكومية»، والأعضاء يُجمَّعون في دفعات الخصم حسب `deduction_entity_id`.
- ⚖️ **تسويات الأسعار** — عند رفع السعر تُنشأ تسوية (خصم الزيادة) للأشهر المتأثرة، تُطبَّق على اشتراك محدد وتُوثَّق بحالتها (pending/applied/cancelled).
- 📦 **دفعات خصم مجمعة** — توليد دفعة شهرية لكل جهة خصم مع عنصر لكل عضو (مبالغ أساسية + تابعين + تسويات) وخطاب جاهز للإرسال، ودورة حالة draft → sent → completed.
- 📊 **تقارير Excel/PDF** — تصدير كشوف الأعضاء والاشتراكات والدفعات، وطباعة الخطابات مباشرة.
- 📥 **استيراد/تصدير Excel** — ترحيل بيانات الأعضاء من الملفات القديمة وتصديرها لأي جهة خارجية.
- 🔐 **أمان RLS** — قراءة لأي مستخدم مسجّل، وكتابة حصرًا لرئيس المجلس والمدير المالي.

│           ├── membership.html         ← واجهة الوحدة (قيد التطوير)
│           ├── membership.css          ← تنسيقات الوحدة (قيد التطوير)

│           └── components/             ← مكونات واجهة قابلة لإعادة الاستخدام
│                                          (جدول الأعضاء، نماذج، بطاقات…) (قيد التطوير)
└── migrations/                         ← ترحيلات القواعد القائمة (تُنفَّذ مرة واحدة)
    ├── 2026-10-01-entity-linkage.sql        ← المرحلة 0 (تسوية الانحراف) + المرحلة 1 (الربط 1:N)

## 🗃️ الجداول (9 جداول + عرض توافقي)

| # | الجدول | الوصف |
|---|---|---|
| 1 | `employers` | جهات العمل (الوزارات، الشركات…) + `scope` (داخلية/خارجية) + `has_deduction_entities` |
| 2 | `deduction_entities` | جهات الخصم — إدارات الاستحقاقات + قالب الخطاب + `employer_id` (1:N) + `is_self` |
| 3 | `membership_types` | فئات العضوية (عامل، منتسب، فخري، داعم) وقواعد التابعين |
| 4 | `membership_fees` | سجل الأسعار التاريخي بتاريخ سريان |
| 5 | `members` | الأعضاء — أساسيون وتابعون عبر `parent_member_id`، ومرابطون بجهة خصم عبر `deduction_entity_id` |
| 6 | `subscriptions` | الاشتراكات الشهرية/السنوية لكل عضو |
| 7 | `fee_adjustments` | تسويات الأسعار (خصم الزيادة عند الرفع) |
| 8 | `deduction_batches` | دفعات الخصم الشهرية + `payment_method` (خصم رواتب/مطالبة نقدية) |
| 9 | `deduction_batch_items` | عناصر الدفعة — سطر لكل عضو + JSONB للتابعين |
| — | `employer_deduction_entities` | **VIEW توافقي** (كان جدول many-to-many) — يُحذف بعد تحديث الواجهة في المرحلة 2/3 |

### 🔗 نموذج الربط بين جهات العمل وجهات الخصم (2026-10-01)

```
employers (جهة عمل)                     deduction_entities (جهة خصم)
┌──────────────────────────┐            ┌────────────────────────────────────┐
│ وزارة التربية             │ 1        N │ وزارة التربية            (is_self) │ ← الصف الذاتي
│ has_deduction_entities=t │────────────│ إدارة استحقاقات التربية  (فرع)     │ ← فرع تابع
│ scope=internal           │            └────────────────────────────────────┘
└──────────────────────────┘
┌──────────────────────────┐            ┌────────────────────────────────────┐
│ شركة النيل (خارجية)       │ 1        1 │ شركة النيل               (is_self) │ ← لا فروع
│ has_deduction_entities=f │────────────└────────────────────────────────────┘
└──────────────────────────┘
┌──────────────────────────┐            ┌────────────────────────────────────┐
│ جهات حكومية (حاوية)       │ 1        N │ جهات حكومية              (is_self) │
│ قرار 8                   │────────────│ وزارة المالية            (مستقلة)  │
└──────────────────────────┘            └────────────────────────────────────┘

members.employer_id ──► members.deduction_entity_id ──► deduction_batches (تجميع حسب الجهة)
```

**قواعد يفرضها المخطط (مشغّلات + قيود):**

| القاعدة | التنفيذ |
|---|---|
| لكل جهة عمل صف ذاتي واحد فقط | مشغّل `trg_employers_ensure_self_entity` + فهرس فريد جزئي `uq_deduction_entities_self_per_employer` |
| لا جهة خصم بلا جهة عمل | مشغّل `trg_deduction_entities_assign_employer` يضمّها للحاوية «جهات حكومية» + `NOT NULL` |
| جهة خصم العضو تتبع جهة عمله | مشغّل `trg_members_link_deduction_entity` — الربط الصريح المتعارض يُرفض (23514) |
| النقل يُبقي العضو على الصف الذاتي | نفس المشغّل: تغيّر `employer_id` ← إعادة الضبط للصف الذاتي للجهة الجديدة (قرار 7) |
| حذف فرع يعيد أعضاءه للصف الذاتي | مشغّل `trg_deduction_entities_reassign_members` |
| دفعة خصم رواتب تتطلب جهة خصم | قيد `deduction_batches_salary_requires_entity` |
| مطالبة نقدية واحدة لكل فترة | فهرس فريد جزئي `uq_deduction_batches_cash_period` |

**دوال مساعدة (تُستدعى من الترحيل أو يدويًا):**
`ensure_container_employer()` · `ensure_self_deduction_entity(employer_id)` · `ensure_all_self_deduction_entities()` · `sync_employer_deduction_flags()`

**الأمان (RLS):**

| العملية | الصلاحية |
|---|---|
| القراءة | أي مستخدم مسجّل (`auth.role() = 'authenticated'`) |
| الكتابة | رئيس المجلس أو المدير المالي (`current_user_role()`) |

## ⚙️ خطوات التثبيت

### 1) Supabase — تنصيبة جديدة

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّل المخطط الأساسي أولًا:
   ```sql
   -- docs/schema.sql  (profiles، current_user_role، الوحدات، الصلاحيات)
   -- docs/seed.sql    (المساحة، الوحدات، التبويبات، التقارير، مصفوفة الصلاحيات)
   ```
3. ثم شغّل مخطط الوحدة:
   ```sql
   -- docs/modules/membership/schema.sql  (v2.0)
   -- 9 جداول + VIEW توافقي + RLS + فهارس + مشغّلات الربط + بيانات أولية — Idempotent
   ```
4. أنشئ المستخدمين من **Authentication → Users** ثم أضف صفًا لهم في `profiles` بنفس الـ UUID مع `role` المناسب (`chairman` / `finance_manager`).

### 1.b) Supabase — قاعدة قائمة (ترحيل)

1. **نسخة احتياطية أولًا**: Database → Backups (أو `pg_dump`).
2. شغّل الترحيل (معاملة واحدة — رجعة تلقائية عند أي فشل):
   ```sql
   -- migrations/2026-10-01-entity-linkage.sql
   ```
   أو من الطرفية:
   ```bash
   psql "$DATABASE_URL" -v ON_ERROR_STOP=1 --single-transaction \
        -f migrations/2026-10-01-entity-linkage.sql
   ```
   ينفّذ الترحيل: المرحلة 0 (أعمدة/قيود كان يستخدمها `membership.js` فعلًا) ثم المرحلة 1
   (نقل العلاقة إلى 1:N، إنشاء الصفوف الذاتية، حاوية «جهات حكومية»، ربط الأعضاء)،
   ويختم بتقرير تحقق يُسقط المعاملة إن اختلّ أي قيد ثابت.
3. تحقّق من النتيجة على نسخة تجريبية:
   ```sql
   -- migrations/2026-10-01-entity-linkage.verify.sql   (35 فحصًا — يُدرج صفوف اختبار ويحذفها)
   ```
4. اختياري: شغّل `docs/modules/membership/schema.sql` v2.0 بعد الترحيل لتوحيد الحالة
   (الملفان idempotent ويصلان إلى النتيجة نفسها).

### 2) GitHub Pages

1. من إعدادات المستودع: **Settings → Pages**.
2. اختر المصدر: فرع `main` والمجلد `/docs`.
3. احفظ وانتظر النشر.

### 3) فتح الموقع

- افتح الرابط المنشور (مثل `https://<user>.github.io/baraka-associations/`) وسجّل الدخول بحساب مدير.

## 📋 خطوات الاستخدام

1. **الدخول** بحساب مدير (رئيس المجلس أو المدير المالي) — الكتابة متاحة لهذين الدورين فقط.
2. **فتح "شؤون العضوية"** من الشريط الجانبي (مجموعة النظام والإدارة).
3. **إدارة البيانات الأساسية:** جهات العمل (بنطاقها الداخلي/الخارجي ومفتاح «لها جهات استحقاق فرعية») وجهات الخصم التابعة لها وفئات العضوية وأسعارها، ثم إضافة الأعضاء وربطهم بجهة العمل — وتُضبط جهة الخصم تلقائيًا على الصف الذاتي حتى اختيار فرع محدد.
4. **تسجيل الاشتراكات:** شهريًا أو سنويًا — نقدًا (بإيصال) أو عبر خصم الرواتب.
5. **توليد دفعات الخصم:** اختيار الشهر وجهة الخصم ← توليد الدفعة المجمنة ← مراجعة العناصر ← إرسال الخطاب ← تعليم الدفعة كمكتملة.
6. **تصدير Excel/PDF** لكشوف الأعضاء والاشتراكات والدفعات عند الحاجة.

## 🚀 الاستعداد للتسويق (Freelance-Ready)
