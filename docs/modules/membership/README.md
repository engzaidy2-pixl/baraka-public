## 📖 نظرة عامة

**نظام شؤون العضوية** هو قلب منصة **بركة** لإدارة الجمعيات الأهلية: يتتبّع العضو من لحظة الانتساب حتى سداد اشتراكاته، سواء نقدًا أو عبر خصم الرواتب.

النظام مصمم لواقع الجمعيات العربية: عضو أساسي (عامل/متقاعد) يرتبط به منتسبون (زوجة، أبناء، والدين)، وكل عضو تابع لجهة عمل وجهة خصم (إدارة استحقاقات)، والأسعار قد تُرفع سنويًا فيُخصم الفارق عن الأعضاء تلقائيًا عبر **تسويات** موثقة.

### 🎯 المشكلة التي يحلها

| قبل بركة | بعد بركة |
|---|---|
| كشوش Excel متفرقة وغير محمية | قاعدة بيانات مركزية بصلاحيات RLS لكل دور |
| حساب الاشتراكات والتأخر يدويًا | اشتراكات شهرية/سنوية بحالة فورية لكل عضو |
| رفع الأسعار يعني مراجعة كل عضو | تسوية سعرية واحدة تُطبَّق على الأشهر المتأثرة تلقائيًا |
| خطابات خصم الرواتب تُكتب يدويًا | دفعة خصم مجمعة لكل جهة شهريًا + خطاب جاهز للطباعة |
| لا سجل تاريخي للأسعار | سجل أسعار تاريخي كامل بتاريخ سريان |

## ✨ المزايا الرئيسية

- 👥 **إدارة الأعضاء** — يدعم 2000+ عضو: بيانات أساسية، تواصل (هاتف/واتساب/بريد)، وظيفة ورقم موظف وراتب، مع بحث سريع بالاسم والرقم الوطني ورقم العضوية.
- 🌳 **بنية هرمية** — منتسبون مرتبطون بعضو أساسي (`parent_member_id` + صلة القرابة)، مع حد أقصى للتابعين لكل فئة وإمكانية تجاوزه (`max_dependents_override`).
- 🏢 **تعدد جهات العمل والخصم** — جهات عمل × جهات خصم (many-to-many) مع جهة خصم افتراضية لكل جهة عمل.
- ⚖️ **تسويات الأسعار** — عند رفع السعر تُنشأ تسوية (خصم الزيادة) للأشهر المتأثرة، تُطبَّق على اشتراك محدد وتُوثَّق بحالتها (pending/applied/cancelled).
- 📦 **دفعات خصم مجمعة** — توليد دفعة شهرية لكل جهة خصم مع عنصر لكل عضو (مبالغ أساسية + تابعين + تسويات) وخطاب جاهز للإرسال، ودورة حالة draft → sent → completed.
- 📊 **تقارير Excel/PDF** — تصدير كشوف الأعضاء والاشتراكات والدفعات، وطباعة الخطابات مباشرة.
- 📥 **استيراد/تصدير Excel** — ترحيل بيانات الأعضاء من الملفات القديمة وتصديرها لأي جهة خارجية.
- 🔐 **أمان RLS** — قراءة لأي مستخدم مسجّل، وكتابة حصرًا لرئيس المجلس والمدير المالي.

## 🗂️ البنية

```
baraka-associations/
├── docs/
│   ├── schema.sql                      ← المخطط الأساسي (profiles، الأدوار، الوحدات)
│   └── modules/
│       └── membership/                 ← وحدة شؤون العضوية
│           ├── README.md               ← هذا الملف (التوثيق)
│           ├── schema.sql              ← مخطط قاعدة البيانات (10 جداول + RLS)
│           ├── seed.sql                ← بيانات أولية موسّعة (قيد الإعداد)
│           ├── membership.html         ← واجهة الوحدة (قيد التطوير)
│           ├── membership.css          ← تنسيقات الوحدة (قيد التطوير)
│           ├── membership.js           ← منطق الوحدة (قيد التطوير)
│           └── components/             ← مكونات واجهة قابلة لإعادة الاستخدام
│                                          (جدول الأعضاء، نماذج، بطاقات…) (قيد التطوير)
```

> 📌 **جاهز حاليًا:** `schema.sql` (مُختبر على PostgreSQL). الملفات الأخرى تخطيط للمرحلة القادمة.

## 🗃️ الجداول (10 جداول)

| # | الجدول | الوصف |
|---|---|---|
| 1 | `employers` | جهات العمل (الوزارات، الشركات…) |
| 2 | `deduction_entities` | جهات الخصم — إدارات الاستحقاقات + قالب الخطاب |
| 3 | `employer_deduction_entities` | العلاقة many-to-many بين جهات العمل وجهات الخصم |
| 4 | `membership_types` | فئات العضوية (عامل، منتسب، فخري، داعم) وقواعد التابعين |
| 5 | `membership_fees` | سجل الأسعار التاريخي بتاريخ سريان |
| 6 | `members` | الأعضاء — أساسيون وتابعون عبر `parent_member_id` |
| 7 | `subscriptions` | الاشتراكات الشهرية/السنوية لكل عضو |
| 8 | `fee_adjustments` | تسويات الأسعار (خصم الزيادة عند الرفع) |
| 9 | `deduction_batches` | دفعات الخصم الشهرية المجمعة لكل جهة |
| 10 | `deduction_batch_items` | عناصر الدفعة — سطر لكل عضو + JSONB للتابعين |

**الأمان (RLS):**

| العملية | الصلاحية |
|---|---|
| القراءة | أي مستخدم مسجّل (`auth.role() = 'authenticated'`) |
| الكتابة | رئيس المجلس أو المدير المالي (`current_user_role()`) |

## ⚙️ خطوات التثبيت

### 1) Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّل المخطط الأساسي أولًا:
   ```sql
   -- docs/schema.sql  (profiles، current_user_role، الوحدات، الصلاحيات)
   ```
3. ثم شغّل مخطط الوحدة:
   ```sql
   -- docs/modules/membership/schema.sql
   -- (10 جداول + RLS + فهارس + بيانات أولية — Idempotent)
   ```
4. أنشئ المستخدمين من **Authentication → Users** ثم أضف صفًا لهم في `profiles` بنفس الـ UUID مع `role` المناسب (`chairman` / `finance_manager`).

### 2) GitHub Pages

1. من إعدادات المستودع: **Settings → Pages**.
2. اختر المصدر: فرع `main` والمجلد `/docs`.
3. احفظ وانتظر النشر.

### 3) فتح الموقع

- افتح الرابط المنشور (مثل `https://<user>.github.io/baraka-associations/`) وسجّل الدخول بحساب مدير.

## 📋 خطوات الاستخدام

1. **الدخول** بحساب مدير (رئيس المجلس أو المدير المالي) — الكتابة متاحة لهذين الدورين فقط.
2. **فتح "شؤون العضوية"** من الشريط الجانبي (مجموعة النظام والإدارة).
3. **إدارة البيانات الأساسية:** جهات العمل وجهات الخصم وفئات العضوية وأسعارها، ثم إضافة الأعضاء الأساسيين وربط المنتسبين بهم.
4. **تسجيل الاشتراكات:** شهريًا أو سنويًا — نقدًا (بإيصال) أو عبر خصم الرواتب.
5. **توليد دفعات الخصم:** اختيار الشهر وجهة الخصم ← توليد الدفعة المجمنة ← مراجعة العناصر ← إرسال الخطاب ← تعليم الدفعة كمكتملة.
6. **تصدير Excel/PDF** لكشوف الأعضاء والاشتراكات والدفعات عند الحاجة.

## 🛠️ التقنيات المستخدمة

| المكوّن | التقنية |
|---|---|
| **قاعدة البيانات** | PostgreSQL 16 (عبر Supabase) |
| **المصادقة** | Supabase Auth (`signInWithPassword`) |
| **الأمان** | Row Level Security (RLS) + دوال `SECURITY DEFINER` |
| **Excel** | SheetJS (`xlsx`) |
| **PDF** | jsPDF + jspdf-autotable |
| **الواجهة** | HTML5 / CSS3 / JavaScript (ES Modules) + Tailwind CSS |

- **🕌 متعدد الجمعيات** — كل جمعية بمشروع Supabase مستقل وبيانات منفصلة تمامًا؛ النشر يستغرق دقائق (ملف schema.sql واحد).
